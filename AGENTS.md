# AGENTS.md — коротке правило роботи v5

У кожного інструмента є лише два обов'язкові файли:

- `tools/<tool-id>/ANCHOR.md` — куди йдемо;
- `tools/<tool-id>/PROGRESS.md` — що фактично зроблено.

Якщо в теці інструмента є `EDITING_RULES.md` і/або `QA_BACKLOG.md` —
вони ТЕЖ обов'язкові до читання перед роботою, нарівні з `ANCHOR.md`.

**Перечитувати ці файли заново перед КОЖНИМ записом у них — не покладатись
на пам'ять чату.** Після стиснення контексту (context compaction) деталі
правил губляться першими, лишаються тільки дати й хеші комітів. Підтверджений
інцидент (26.08.2026): запис перезаписано поверх чужого через покладання на
пам'ять замість повторного читання файлу.

## Для будь-якого агента

Перед роботою прочитай `ANCHOR.md`. Працюй тільки в його межах. Якщо якоря немає — створи його з ідеї власника і дочекайся погодження, перш ніж писати код.

Після роботи додай у `PROGRESS.md` один запис:

```
Дата:
Агент:
Зроблено:
Файли / commit:
Перевірка або відхилення:
```

Якщо в теці є `QA_BACKLOG.md` — після завершення пункту повідомити Guardian
(через власника) окремим коротким звітом. Не покладатись на те, що звіт уже
надсилався раніше в цьому чаті.

Не змінюй `ANCHOR.md` самостійно. Якщо завдання суперечить якорю — зупинись і напиши в `PROGRESS.md` коротко, у чому розбіжність.

Якщо не впевнений у правилі чи процедурі — запитай власника, не вигадуй.

## Роль Guardian — Codex

Коли власник пише `Мітинг: <tool-id>`, я сам знаходжу всі зміни після останньої перевірки, порівнюю їх з `ANCHOR.md` і обговорюю результат з власником.

Після мітингу я або:
- фіксую, що рух правильний;
- письмово вказую, що повернути або виправити;
- після погодження власника оновлюю `ANCHOR.md`.

Для старту будь-якого агента власнику достатньо однієї фрази:

```
Прочитай AGENTS.md у цьому репозиторії. Моє завдання: <опис своїми словами>.
```

Детальна роль контролю: `GUARDIAN.md` (якщо файл відсутній у репозиторії —
звернутись до власника, не вигадувати його вміст).
