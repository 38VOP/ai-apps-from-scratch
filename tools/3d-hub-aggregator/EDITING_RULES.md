# EDITING_RULES — 3d-hub-aggregator

**Версія:** 1.1
**Дата:** 18.08.2026
**Причина:** обмежені ліміти використання агентів + ризик, що будь-яке точкове 
прохання перетворюється на повне переписування файлу

Це правило застосовується до КОЖНОГО завдання агенту в цьому інструменті, 
незалежно від того, чи згадано це явно в конкретному промпті.

## Обов'язково

1. **Тільки точкові зміни.** Якщо завдання — виправити баг або додати одну 
   функцію, редагуй мінімальну ділянку коду. НЕ переписуй весь файл, НЕ 
   регенеруй компонент з нуля, навіть якщо здається, що "так буде чистіше".
2. **Заборонено "покращувати" по дорозі.** Не рефакторити сусідній код, не 
   перейменовувати змінні, не міняти стиль форматування — якщо це прямо не 
   запитано.
3. **Diff, а не replace.** Зміни повинні виглядати як точковий diff (кілька 
   рядків додано/змінено), а не як заміна файлу повністю новим вмістом. Якщо 
   інструмент дозволяє — використовуй патч/edit-функцію, а не "написати файл 
   заново".
4. **Явний виняток — рефакторинг.** Повне переписування структури дозволене 
   ТІЛЬКИ коли завдання прямо називається "рефакторинг" і описує саме це.
5. **Якщо не вкладаєшся в ліміт** — краще виконати менше пунктів повністю і 
   чесно, ніж усі пункти частково і мовчки. Зупинись, зафіксуй у PROGRESS.md, 
   що встигнув, а що ні.
6. **Файли створюй/редагуй тільки штатним інструментом редактора** (write 
   file / edit file вашого агента), НІКОЛИ через обхідні трюки на кшталт 
   `python -c "content = '''...'''; open(...).write(content)"` у терміналі. 
   Такий підхід ламається на будь-яких лапках/спецсимволах усередині JSX/коду 
   (підтверджений збій: спроба записати Cart.jsx через python-скрипт у 
   терміналі впала з `SyntaxError: unterminated triple-quoted string literal`, 
   18.08.2026) і призводить до втраченого часу та ліміту без жодного 
   результату.
7. **Якщо штатний інструмент запису файлу не спрацював (помилка, зависання, 
   файл завеликий)** — НЕ шукай обхідний шлях і не імпровізуй. Розбий вміст 
   файлу на менші частини і запиши штатним інструментом послідовно (кілька 
   менших edit-операцій замість однієї великої), або зупинись і чесно 
   зафіксуй проблему в PROGRESS.md з описом, що саме не вдалось.

## Чому це правило існує

Раунд 4 (14-15.08.2026): агент отримав список із 7 точкових правок, але 
результат показав ознаки повного переписування файлів (втрачено форматування 
ANCHOR.md, розбіжність між заявленим і реальним кодом). Власник має обмежені 
ліміти використання платних агентів — кожне зайве повне переписування коштує 
реальних грошей і часу без потреби.
